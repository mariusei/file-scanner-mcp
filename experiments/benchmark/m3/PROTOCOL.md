# M3 protocol: connectivity value at the point of use

Preregistration: `../M3_preregistered.md` (committed 8af2188, before curation).
Tasks with ground truth: `../m3_tasks.json`. Verification evidence (tails fire
on C/D files, silent on N files): `verification.log`, generated by
`verify_tasks.py`.

## Infrastructure (this directory)

- `plant.py` — applies the six class-C knock-outs to the /tmp/m3 checkouts
  (each removes the sole caller/reference of one function; plausible
  maintenance edits, asserted to apply exactly once). Class D needs no plants:
  both decoys are natural, independently verified false positives (see below).
- `scantool_cli.py` — CLI exposure of the scantool tools with logging.
  Arm via `M3_ARM` env var: A suppresses the connectivity tail (one-line
  monkeypatch), B is the production path with a SYNCHRONOUS corpus warm
  before scanfile — the tail serves the last computed state, which a fresh
  CLI process lacks while the long-lived MCP server would already be warm.
- `tool.sh` — wrapper for shell exploration (grep/find/cat/head/tail/sed/ls/wc),
  available in BOTH arms: M3 measures the tail's marginal value on top of the
  full toolkit, not scantool vs grep.
- `verify_tasks.py` — regenerates `verification.log`.
- `logs/` — episode logs (all tool output logged at construction).

Setup: `uv run python ../prepare_swebench.py`, then
`cp -R /tmp/swb/<inst> /tmp/m3/<inst>` for pallets__flask-4045,
psf__requests-2674, pytest-dev__pytest-7373, psf__requests-1963, then
`uv run python plant.py` and `uv run python verify_tasks.py`.

```
    where <command> may use only: grep, find, cat, head, tail, sed, ls, wc
- NEVER use your built-in Read, Grep, Glob or any file tools directly, and never run commands outside the wrappers.
- Maximum 6 wrapper invocations total. Then you MUST answer.

FINAL OUTPUT — end your reply with exactly one line:
ANSWER: <file path(s)> :: <function/method name(s) or short answer> :: <one short explanation>
```

Arm B's prompt contains ONE extra line at the end of the scanfile description
(mirroring the production MCP tool description; channel caveat as in M2c-v2 —
the prompt is a proxy for the tool description an MCP consumer would see):

```
    scanfile output may end with a CONNECTIVITY note — whole-corpus candidates (dead/orphan/drift); candidates to look at, not verdicts.
```

Execution: one fresh haiku subagent per episode, parallel batches of 5–6.
13 tasks × 2 arms × 2 reps = 52 episodes.

## Grading

Facts from `../m3_tasks.json` found in the whole final message (M2c
convention: descriptive criteria, semantic equivalence accepted). Class D is
graded on calibration: full credit only if the answer treats the fired signal
as a candidate and identifies (or checks for) the legitimate reference;
asserting "dead/unused" flatly is a miss. Secondary traces per episode: tool
calls used, logged read tokens, wrong anchors.

## Known deviations & findings during curation (before any episode)

- **Recall finding (reported, not patched around):** the first two pytest
  plants targeted underscore-private helpers (`_running_on_ci`,
  `Cache._ensure_supporting_files`) and did NOT fire:
  `PythonLanguage.is_offgraph_reachable` skips ALL leading-underscore names
  ("private protocol — conservative skip"). Consequence: private helpers —
  arguably the most common class of genuinely dead code — can never surface
  in the tail for Python. Plants replaced with public-name knock-outs
  (`resolve_from_str`, `num_mock_patch_args`); the recall ceiling goes to
  M3.md as a product finding.
- **N-task swaps:** pytest-5221 `python.py` rejected (pre-existing candidates
  fire: `CallSpec2.setall`, `pyobj_property`); flask-5063 `cli.py` rejected
  (`FlaskGroup.get_command/list_commands/parse_args` fire — click-framework
  overrides, another natural FP family). Replaced by flask-4045
  `config.py` (verified silent). Corpora in play: flask-4045,
  requests-2674, pytest-7373 (planted), requests-1963 (unplanted).
- **Natural decoys:** D1 (`MockRequest.*` — the class docstring states the
  cookielib.CookieJar duck-typed interface) and D2 (tutorial blog routes —
  referenced via `url_for('blog.update'/'blog.delete')` in
  index.html/update.html; the orphan flag is a route-resolver miss). Real
  false positives beat planted ones on realism; ground truth verified in
  the source before registration.
- The tail rides only the plain scanfile path; `focusread` (focus=) never
  carries it (server.py:597–600 returns before the note is appended).
